# v0.5.2 — drop the dormant `fs2` dependency

v0.5.2 is a patch release with no behavior change and no new dependency. It removes the dormant, archived `fs2` crate (last published 2018-01-06) in favor of a small in-repo advisory-locking helper over `libc::flock(2)`, and `libc` is already a direct dependency. `fs2`'s own Unix backend is `libc::flock(fd, LOCK_EX | LOCK_UN)`, so the replacement invokes the same syscall with the same flags.

## What changed

- `fs2` is gone from the dependency tree (`cargo tree -i fs2` finds nothing), along with the transitive `winapi` / `winapi-*-pc-windows-gnu` packages it pulled in for Windows locking that uhm never used.
- A new `src/file_lock.rs` provides exactly the surface uhm relied on — blocking-exclusive `lock_exclusive` and explicit `unlock` — over `libc::flock(2)`. Telemetry's eager explicit unlocks and the recovery / history / first-run drop-on-close behavior are both unchanged.
- The MSRV (1.82), every conversation boundary, tool set, and wire contract are unchanged.

## Not a security fix

`fs2` carries no RUSTSEC advisory. This is dormant-dependency hygiene — the crate was archived in 2018 — not a vulnerability remediation.

## Verification

The full Rust suite (269 library + integration tests, including a new test that pins the blocking-exclusive lock contract), `cargo clippy -D warnings`, `cargo fmt --check`, MSRV 1.82 checks on both glibc and musl, `scripts/check-docs.py`, and `scripts/provider-bakeoff.py --self-test`.
