# v0.6.5 — harden execution isolation, recovery, and command classification

v0.6.5 is a hardening release. It closes several command-classification and
process-control bypasses, makes recovery resilient to a single corrupt manifest,
and adds dormant plumbing for signed releases. The updater continues to verify
downloads over TLS plus the SHA-256 check, now with a notice that release signing
is not configured yet; signing only takes effect once a key is added.

## What changed

### Execution isolation

The final reap after `SIGKILL` is now bounded. A child stuck in uninterruptible
sleep (a hung page-in, NFS, or device ioctl) is not killed until its syscall
returns, so a blocking wait could previously hang `uhm` forever. After a short
grace, `uhm` reports the pending `SIGKILL` honestly and lets the kernel reap the
reparented zombie when it exits.

Children also enter their own process group from the parent side, closing the
race where a signal delivered between fork and the child's own `setpgid` silently
missed escalation. Once the leader is reaped, the group is no longer signaled, so
a recycled pid (notably under `sudo` or `pkexec`) cannot be struck.

### Recovery resilience

A single unreadable or invalid recovery manifest used to fail the whole scan,
wedging status, selection, and even `prune` (the natural remedy) behind the same
bad file. The scan now skips and records each corrupt run with its reason; status
and prune report them, and `uhm recovery prune --run <id>` force-removes one by id.

### Command classification

Interior backslash escapes (`r\m`), transparent command wrappers (`pkexec`,
`strace`, `chroot`, `fakeroot`, `firejail`, `proot`, `busybox`), and remote
destructive commands (`ssh host rm`) can no longer slip past the local review
gate. Additional Unicode format controls and the `U+2028`/`U+2029` line and
paragraph separators are now escaped in untrusted text.

### Release signing groundwork (dormant)

`uhm update` now carries the plumbing to verify a detached minisign (Ed25519)
signature over `SHA256SUMS` before trusting the manifest. Once a signing key is
compiled in, the update fails closed on a missing or invalid signature; while the
placeholder key remains, it warns and falls back to TLS plus the checksum check.
The release workflow can sign the manifest and cross-check the signature against
the compiled-in key. This changes nothing for users until a key is configured;
see `docs/reference/release-signing.md`.

This release also fixes semver prerelease and downgrade ordering in the updater
and scrubs inherited CA-bundle environment before running the installer.

## Verification

The release passed `cargo fmt --all -- --check`,
`cargo clippy --all-targets --locked -- -D warnings`,
`cargo test --all-targets --locked`, `python3 scripts/check-docs.py`, the
installer portability test and its tampered-checksum negative test, and
`python3 scripts/provider-bakeoff.py --self-test`.
