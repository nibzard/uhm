# v0.3.4 — managed-network trust and transport diagnostics

v0.3.4 fixes HTTPS compatibility for managed and corporate environments that route traffic through a private-CA HTTP CONNECT proxy.

- **Native and custom trust.** All outbound clients load platform roots, honor `SSL_CERT_FILE` and `SSL_CERT_DIR`, and append explicitly configured roots from `UHM_CA_BUNDLE`. Invalid configured trust fails before a request; certificate verification cannot be disabled.
- **Explicit proxy policy.** HTTPS prefers `HTTPS_PROXY`, then `ALL_PROXY`, then `HTTP_PROXY`; uppercase and lowercase forms are supported. `NO_PROXY` handles hosts, suffixes, ports, IPv4, and bracketed IPv6.
- **One transport implementation.** Live provider calls, `doctor network`, and telemetry use the same proxy resolver, root store, TLS configuration, timeout policy, and safe failure classifier.
- **Layer-specific diagnostics.** Doctor distinguishes trust setup, proxy setup, CONNECT, DNS, TCP, certificate verification, TLS handshake, HTTP, and authentication. Machine-readable provider failures distinguish `trust`, `proxy`, `dns`, `tls`, and `network` without exposing secrets.
- **Packaged-binary regression gate.** CI and release builds run the compiled artifact behind an HTTP CONNECT proxy whose `api.openai.com` certificate is signed by a private test root. The gate requires fail-closed rejection without the root and HTTP `401` reachability through `SSL_CERT_FILE`, `SSL_CERT_DIR`, and `UHM_CA_BUNDLE`, including the live Responses route.

Verification includes the complete Rust suite, strict Clippy, documentation checks, native release testing, static musl testing, and the offline private-CA CONNECT fixture. The fixture uses an intentionally invalid token and never contacts the public API.
