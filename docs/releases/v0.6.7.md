# v0.6.7 — harden recovery, probing, and release assurance

v0.6.7 is a correctness and reliability release following a full adversarial
review of the managed recovery, local discovery, provider qualification, and
telemetry paths. It preserves the public CLI contract while making interrupted
operations and bounded subprocess behavior match the guarantees already shown
to users.

## What changed

### Recovery and durability

- Managed writes now sync staged files, snapshot directories, created ancestry,
  and destination directories before later state is acknowledged.
- Partial commits containing newly created files resume from positive staged
  evidence instead of requiring replacement-only metadata.
- Interrupted undo reconciles from recorded bytes and modes. Creation removals
  persist and preflight an exact quarantine identity, including forced retries,
  before any output is changed.
- Completed restore items verify both bytes and permissions, malformed resume
  evidence fails closed, and durability failures remain honestly resumable.

### Bounded local discovery and consent

- Automatic tool discovery runs only the disclosed `--help` form. Every probe
  uses one bounded collector, retains process-group ownership through cleanup,
  and terminates descendants even when the direct child exits successfully.
- Python inventory is collected once per request, failed Git status is reported
  as unavailable, and oversized output is cancelled at its configured limit.
- Consent distinguishes an unavailable prompt from an explicit decline. Human
  response time no longer consumes the shared machine probe budget, and the v2
  consent store migrates prior allowed decisions conservatively.

### Provider and telemetry correctness

- Clarification follow-ups carry both the displayed question and the user's
  answer through every provider adapter.
- Qualification checkpoints resume after their audit pause only when the stored
  judgment could have been produced by the runner's eligibility rules. Runtime
  action kinds use the Rust-authoritative mapping.
- The telemetry gateway accepts the shipped v2 payload, retains v1 compatibility,
  and stops reading oversized streams at the limit.

### Maintenance and documentation

- History export no longer changes permissions on a directory chosen by the
  user, including the current directory default.
- CI now gates the Rust, Python, real telemetry-contract, documentation,
  installer, MSRV, and dependency boundaries added by the review.
- `rustls` and Worker tooling include the reviewed security updates, and the
  user documentation was reorganized around the current provider, privacy, and
  recovery behavior.

## Verification

The release passed formatting, Clippy with warnings denied, every Rust target,
the Rust 1.89 MSRV check, the offline Python suite and provider self-test,
documentation and installer checks, Worker tests, the real telemetry contract,
Cargo advisory/license/source gates, npm audit, crate packaging, and an optimized
release build. Live provider calls, a deployed Worker, and physical power-loss
testing remain outside this release gate.
