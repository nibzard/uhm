# v0.3.5 — microprograms on version-managed Python and truthful review options

v0.3.5 repairs the Python microprogram route on hosts where `python3` is provided by a version manager, and stops the shell review and repair prompts from offering choices they cannot honor.

- **Microprograms run under pyenv, asdf, and mise.** Both program spawn sites built the cleared child `PATH` from the interpreter's own directory alone. A version-managed interpreter is a shell script that resolves itself through `#!/usr/bin/env bash`, so it exited `127` with `env: bash: No such file or directory` and every program-route job failed. Both sites now use the shared minimal path that already carries the system binary directories, which is why runtime inventory and `uhm doctor` reported a working interpreter while execution did not. The defect shipped in every release from v0.2.0 through v0.3.4.
- **Review offers only what it can run.** The shell review prompt always printed `[R/v/e/c/q]`, but revision needs an unspent replacement slot and editing needs an unused replacement. After a repair consumed that slot, an advertised key fell into the cancel arm and silently ended the job. The prompt is now derived from the live option set, and a key that exists but is not offered explains the exhausted budget and re-prompts instead of cancelling.
- **Repair receives child output or asks for it.** The repair request carried `uhm`'s own "diagnostics unavailable" notice in the field reserved for child diagnostics. That field is now null when no stderr tail was retained, and because the remaining seed holds only the inputs that already failed, repair asks for the observed error and declines rather than resending the same command.
- **Interactive review has direct coverage.** A pty keystroke harness now drives the review prompt on both supported hosts; the previous fixture was Linux-only and supplied closed stdin, so it could exercise cancellation but never a choice.

Verification includes the complete Rust suite, strict Clippy, documentation checks, native release testing, static musl testing, and the offline private-CA CONNECT fixture. The fixture uses an intentionally invalid token and never contacts the public API.

Terminal-attached child stderr is still inherited and retains no diagnostic tail, so repair after an interactive failure depends on the observed error the user supplies. Retaining a bounded tail without hiding the terminal from the child is planned work and changes a documented stream promise.
