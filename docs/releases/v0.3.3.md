# v0.3.3 — operational containment and release assurance

v0.3.3 follows the clean-room v0.3.2 assessment with defense-in-depth controls and release-process improvements.

- **Opt-in Linux containment.** `execution.containment: bubblewrap` runs shell and generated-Python children without network access, with a read-only host root and writable invocation/workspace roots. Requested containment fails closed when Bubblewrap is unavailable.
- **Broader credential protection.** `execution.deny_common_env` removes a conservative preset of common cloud, CI, database, registry, Kubernetes, Vault, Docker, and SSH-agent capabilities. `uhm doctor environment` reports recognized inherited names without exposing their values.
- **Portable installation.** The installer now falls back through `TMPDIR`, `XDG_RUNTIME_DIR`, `/tmp`, and a private user-cache directory, covering minimal environments where `/tmp` is absent.
- **Stronger release evidence.** GitHub releases now include an SPDX JSON SBOM with an SBOM attestation in addition to existing build provenance and checksums.
- **Provider test infrastructure.** A manually dispatched, credential-backed smoke workflow exercises the compiled provider adapters while retaining only content-free summaries. Regular CI now detects offline provider-runner contract drift.
- **Deterministic benchmark fixtures.** The checked-in execution corpus now tracks prompt contract v12 and regenerates with stable map ordering.

Verification included formatting, strict Clippy, documentation and workflow checks, 421 Rust tests, installer portability coverage, the offline provider-runner self-test, telemetry-worker tests, an optimized release build, and crate packaging. The credential-backed smoke workflow requires repository secrets and is intentionally run through GitHub Actions.
