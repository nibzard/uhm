# uhm v0.2.1

A fix release. It corrects five defects found while retesting v0.2.0 in environments the earlier build did not exercise — corporate proxy egress, CI and managed enterprise hosts — plus version-text and disclosure-consistency issues surfaced in the same pass. No new surface area is added; behavior contracts are tightened.

## What ships

- **Environment proxy support.** The OpenAI client, the `uhm doctor network` probe, and the telemetry uploader now honor `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` (and lowercase variants). ureq opt-in proxy detection was off by default, so v0.2.0 failed with DNS errors on controlled-egress networks where a proxy is required. All three HTTP agents now enable `try_proxy_from_env`.
- **`uhm doctor` exit reflects overall health.** The exit status is no longer based only on OS/architecture support. `uhm doctor` exits 13 if any non-optional check fails — host, API key, paths, network, shell, or Python runtime — and 0 only when all checks pass. `uhm doctor network && …` is now a real gate for CI and enterprise hosts. `--json` reports the same `exit_code`.
- **Invalid overrides are usage errors.** `uhm --shell <bad>` and `uhm --context <bad>` now fail with exit 2 (invalid invocation) at parse time, before API-key resolution, instead of exiting 13 (credentials) when no key is set.
- **Local commands no longer trigger the outbound disclosure.** Purely local subcommands such as `uhm config show`, `uhm context show`, `uhm history …`, `uhm telemetry status|preview`, and `uhm doctor` (without `network`) no longer print the first-use data notice or write the notice marker. The notice is rendered before the first actual outbound request, matching the documented contract.
- **Version-text residuals.** The doctor host hint and the telemetry `release` examples in `PRIVACY.md` and the privacy guide now reflect the current version instead of the v0.1 text the 0.1.0 → 0.2.0 bump left behind.

## Execution policy

Unchanged from v0.2.0. Ordinary actions run immediately; detected deletion, broad writes, privilege elevation, remote mutation, or process control pause unless `--force` is explicit; `--review` pauses every proposal; `--dry-run` prints exact command bytes and runs nothing. These warnings are advisory and are not a sandbox or a safety guarantee.

## Limits

Unchanged from v0.2.0. Linux and macOS are supported; native Windows is not. macOS archives remain unsigned and unnotarized in this release. `uhm` is still not a background agent, provides no universal undo, and does not sandbox model-generated commands or programs.

The `uhm-cli` crate continues to pass packaging and publish dry-run checks; publishing to crates.io remains deferred until registry ownership is ready. GitHub binaries and `cargo install --git` are the supported channels.
