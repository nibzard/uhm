# v0.3.6 — no prompt offers what it cannot honor

v0.3.6 completes the interaction repair started in v0.3.5. That release fixed the shell review prompt without auditing the other interactive states, and two of them had the same defect.

- **Program review offers only live options.** The program review prompt was an unaudited copy of the shell one: a fixed `[R/v/e/c/q]` whose revise and edit branches required a replacement budget that a prior clarification or repair may already have spent, with every unmatched key falling through to cancellation. Both prompts now share one option derivation, prompt rendering, and key resolution, so no hardcoded review prompt remains outside test assertions and the two cannot drift apart again.
- **An ended job states instead of asking.** When a clarification could not be continued, `uhm` announced the exhausted budget and then rendered the outstanding question anyway, so a closed job finished by asking something with no prompt to answer it. The question keeps its place on stdout, leaving the documented output contract and the `--json` `message` field unchanged; the surrounding lines now say that the job ended and that the request should be re-run with the missing detail included.
- **Remaining prompts audited.** The evidence-profile replacement, program contract repair, program failure, shell failure, and unavailable-requirement alternative prompts were each confirmed to be gated by the budget they require. No behavior changed for them.

Verification includes the complete Rust suite, strict Clippy, documentation checks, native release testing, static musl testing, and the offline private-CA CONNECT fixture. The fixture uses an intentionally invalid token and never contacts the public API.

A clarification still consumes the job's second model call, so a command generated from a clarified request has no repair turn left if it fails. Requests naming a tool outside the bounded context catalog remain the case where that matters most, because the model is not given the tool's own interface and cannot discover it. Supplying observed tool capability is planned work and changes what leaves the device, so it is not part of a patch release.
