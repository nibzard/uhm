# v0.6.1 — drop the unmaintained `rustls-pemfile` dependency

v0.6.1 is a patch release with no behavior change. It migrates the one
certificate-parsing call site from `rustls-pemfile` to `rustls::pki_types::pem`
(the `PemObject` API) and removes `rustls-pemfile` from the dependency tree.

## What changed

- `src/http.rs` parses a `UHM_CA_BUNDLE` PEM file with
  `rustls::pki_types::CertificateDer::pem_reader_iter` instead of
  `rustls_pemfile::certs`. The same bytes parse into the same
  `CertificateDer<'static>` values, so trust-store population is unchanged.
- `rustls-pemfile` (RUSTSEC-2025-0134, unmaintained) was a direct dependency of
  `uhm-cli` only; migrating removes it from the tree entirely. `rustls-pki-types`
  was already present via `rustls`, so no dependency is added. The locked package
  count drops from 104 to 103.
- `cargo deny check` is now advisory-clean with no ignored advisories; the
  `RUSTSEC-2025-0134` ignore is gone.

## Not a security fix

`rustls-pemfile` carries an *unmaintained* advisory, not a vulnerability
advisory. This is dependency hygiene on top of the v0.6.0 changes — fewer
dependencies, no ignored advisories — not a remediation.

## Verification

-D warnings`, `cargo fmt --check`, the `cargo +1.89.0 check` MSRV gate,
`cargo deny check` (advisories, licenses, bans, sources — all clean),
