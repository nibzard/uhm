# v0.6.2 — close review-gate bypasses found in a full-project audit

v0.6.2 is a patch release from a full review of the project. It closes several
paths by which a model-authored action could reach execution without the review
card the execution gate depends on, fixes a reachable panic, corrects three
consent prompts that named the wrong provider, and syncs the privacy contract
with what the code actually sends.

## Why these are gating bugs, not warning bugs

Both executable routes compute `consequential` from the local classifier and the
declared effect set, and `review` is `args.review || consequential`. `--review`
is off by default, so when `consequential` is false there is no preview card and
no confirmation — control falls through to execution. A gap in `safety::classify`
is therefore silent execution of a model-authored command, not a missing warning.

The model's own declared effects are merged with the classifier's, and
`delete_local` forces a pause, so both layers had to miss for a command to run
unreviewed. The local classifier exists precisely because the model's declaration
cannot be trusted, so a gap in it is worth closing on its own terms.

## What changed

### Command classification (`src/safety.rs`)

Three defects let ordinary model-authored idiom through untiered:

- `split_segments` treated a backslash as an escape inside single quotes, where
  POSIX shells do not. `echo 'a\' ; rm file.txt` swallowed the closing quote and
  absorbed the rest of the line into one unclassified segment. The two
  neighbouring parsers, `has_output_redirection` and `has_dynamic_shell_syntax`,
  already guarded this correctly.
- `first_command_word` stopped at the first token that was neither an assignment
  nor a known wrapper, so a wrapper's own flag became the command word and every
  command-specific rule was skipped: `xargs -0 rm`, `xargs -I{} rm {}`,
  `env -i rm`, `command -p rm`. A wrapper's options and numeric operands are now
  skipped once a wrapper has been seen, which only ever looks further for the
  real command word. `timeout`, `nice`, `ionice`, `setsid`, `stdbuf`, `watch`,
  and `busybox` join the wrapper set.
- `normalized_command` stripped a leading backslash and a directory prefix but
  not quotes, so `"rm" -rf` matched no rule; the lethal-substring backstop missed
  it too, because the quote sits between the command and its flags.

`xargs -0 rm`, `timeout 5 rm`, `"rm" -rf`, and `echo 'a\' ; rm file.txt` now
classify as Destructive or Irreversible. `ls -la`, `git status`, and
`echo 'back\slash is fine'` still classify as None.

### Unicode format characters (`src/action.rs`, `src/render/ansi.rs`)

`ProposedAction::validate` and `sanitize_untrusted` both gated on
`char::is_control`, which is Unicode category `Cc` only. Terminal escape
injection was blocked, but category `Cf` was not: `U+202E RIGHT-TO-LEFT
OVERRIDE`, the isolate controls, zero-width separators, and the BOM reached the
review card verbatim. A bidi override changes how an operand renders without
changing the bytes that run, so a destructive command could display as a
harmless one and be approved. `is_format_control` now backs both the sanitizer
and the action validator. Ordinary non-ASCII text is unaffected.

### Reachable panic (`src/tool_surface.rs`)

`truncate_help` sliced a `String` at a raw byte index. The top-level probe always
hit the early return, but `assemble_help` passes a remaining budget that is
arithmetic rather than a char boundary, so subcommand help containing an arrow or
box-drawing character across that offset panicked the process. The damage
persisted: the text lives in `tool-surface.json`, so every later request naming
that tool panicked until the store was deleted by hand.

### Consent prompts (`src/main.rs`)

The shell-history, `uhm repair`, and `uhm recover` prompts each hardcoded "sent
to OpenAI". With `provider: cerebras` or `deepseek` the user consented to sending
data to a party that would not receive it, and was never told who would. All
three now name the configured provider.

### Privacy contract (`PRIVACY.md`, `docs/privacy.md`)

- Both documents introduce the interaction summary as "exactly these fields" and
  then listed 17 of the 18 that go on the wire. `expansion_outcome` is now
  documented with its enum values, and `notice_revision` was corrected from 4 to
  5. The list is taken from `uhm telemetry preview`, so it matches the wire.
- `shell_context.last_history_entry` was absent from the privacy contract
  entirely, though it sends a previous shell command line to the provider and
  such a line routinely contains credentials. The runtime gate was already sound
  — off by default, wrapper-only, printed in full, terminal approval required —
  but an undisclosed channel is a contract gap regardless of how well it is
  gated.

### Supply chain and packaging

- `deps.yml` ran `cargo deny` under `continue-on-error`, so it could not fail
  anything. Its own comment deferred promotion until `rustls-pemfile` was
  migrated, which landed in v0.6.1, and `deny.toml` carries no ignore list. The
  job is now gating; `cargo deny check` is clean across advisories, licenses,
  bans, and sources.
- `benchmark/docker/Dockerfile` built from `rust:1.82` against an MSRV of 1.89,
  so `build-worker.sh` — the entry point for the qualification workflow — could
  not build. Nothing in CI builds this image, so it failed silently.
- Three fixtures reached by `include_str!` were excluded from the published
  crate, so `cargo test` could not compile from a release tarball. All five
  fixtures now ship.

## Not included

Two findings from the same audit need design work rather than a patch and are
deliberately not in this release:

- The shell route's output threads use blocking reads joined after the child
  exits, so a backgrounded grandchild holding the pipe can block `uhm` past its
  own timeout. `CHILD_GROUP` is cleared before the joins, so the SIGINT handler
  cannot interrupt it. `program.rs` already solves this with nonblocking
  descriptors and an absolute deadline; porting it touches signal handling.
- Recovery run directories are never removed, and past `recovery.scan_limit` the
  selection, status, and prune paths silently truncate in filesystem order, so
  `uhm undo last` can select an older manifest. Capture fails closed on the same
  overflow while selection fails open, which suggests the retention policy was
  never settled.

## Verification

`cargo fmt --check`, `cargo clippy --all-targets --locked` (no warnings), the
full Rust suite (275 library, 51 CLI-contract, and 2 corpus/docs tests),
`cargo +1.89.0 check --locked` for the MSRV gate, `cargo deny check` (advisories,
licenses, bans, sources — all clean), `scripts/check-docs.py`, and
`cargo package --list` for the fixture set.
