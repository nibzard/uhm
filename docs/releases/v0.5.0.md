# v0.5.0 — subcommand probe expansion and the DeepSeek provider

v0.5.0 adds two capabilities and tightens one privacy guarantee.

## The subcommand probe expansion (plan 18)

When a request names an installed tool whose top-level help advertises a subcommand group but omits the verb the target needs, the model may now ask the host — never the user — to read that one subcommand's help under the consent already given, then re-propose from the deepened surface. The host builds and validates the probe; the model only names one subcommand token. It is one extra model call the first time a tool's depth is needed, and the result is persisted, so the next request naming the same tool carries the deeper surface in its first call and is a one-call job again.

- **Behavior change: the conversation boundary moves from two calls to three.** This is what makes it a minor release. A job may now spend at most one *probe expansion* in addition to its initial call and its one replacement slot: initial call + at most one machine-answered probe expansion + the one revision/edit/repair slot, bounded, no loop. The expansion is slot-neutral — it consumes neither the replacement slot nor an execution — so `revise`, `edit`, and `repair` remain offered afterwards exactly as before. `probe_subcommand` is omitted from the follow-up call after a probe, so a second probe in one job has no tool to call; nesting is impossible by construction.
- **The model never chooses the probe.** It names one tool already shown in the surface and one subcommand token that appears verbatim as a word in that tool's retained top-level help. The host resolves the binary, confirms its identity still matches the consented record, and runs `[path, subcommand, --help]` with the existing help-flag fallback, deadline, and byte caps. The model never selects argv, flags, or paths, and a tool that changed between calls is re-consented rather than silently probed.
- **Nothing new leaves the device.** The probe reads a binary's own subcommand help locally, under the same per-binary consent Plan 16 already discloses; probing more of a tool's help gains no authority the first consented probe lacked. Help output stays untrusted and is sanitized before it can reach a request. Receipts and telemetry record only a coarse outcome enum (`none`, `probed`, `probe_empty`, `invalid_probe`); the tool name, subcommand, and help bytes never appear in telemetry or metadata history.
- **Availability and failure are honest.** The expansion is offered only on the first call of a `run` or `recover` job, never on `ask` or `explain`. An invalid probe (an un-nameable tool, a subcommand the help did not advertise, an already-spent expansion) terminates with an `invalid_probe` receipt instead of executing or re-asking. A probe that finds no readable help makes its one follow-up call with the surface unchanged and states the empty result.

The live measurement is recorded in plan 18: the motivating intent composed correctly in 12 of 12 samples with the probe firing each time, and no spurious probes fired on intents that named no tool.

## DeepSeek provider

DeepSeek is now a built-in provider behind the same canonical action validator. It speaks the OpenAI Responses API format, so it shares the wire contract; one divergence is that DeepSeek thinking mode rejects `tool_choice: "required"`, so the adapter uses `"auto"` while the parser still requires exactly one completed call. Select it with `--provider deepseek` and `DEEPSEEK_API_KEY`. It is **experimental-unqualified** under fixed selection: usable, but without the reviewed holdout evidence that would let evidence mode select any pair automatically.

## Credential isolation now covers DeepSeek

Child-process credential isolation now removes `DEEPSEEK_API_KEY` as well as `OPENAI_API_KEY` and `CEREBRAS_API_KEY` from generated shell and program children; a proposed command that reads or prints any of the three is blocked; and the developer instructions name all three. This closes a gap the DeepSeek adapter opened and matches the guarantee `docs/configuration.md` already stated.

## Verification

The complete Rust suite (including the pty contract suite), strict Clippy, new unit tests for every probe validation rule and the budget invariant, an adversarial review of the diff, and the live measurement recorded in plan 18.

The boundary's purpose — keep one intent faster than recalling syntax, with no user-facing turn loop — is unchanged; only its letter moves from two calls to three, and the amortized count returns to one as the persisted subcommand surface warms.
