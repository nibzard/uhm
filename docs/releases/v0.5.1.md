# v0.5.1 — per-provider default model and a privacy clarification

v0.5.1 is a patch release: it fixes one default-model defect from v0.5.0 and clarifies one privacy-disclosure sentence. No conversation boundary, tool set, or wire contract changes.

## Per-provider default model

`Config::defaults` seeded the OpenAI model (`gpt-5.6-terra`) for every provider, so `--provider deepseek` (or `cerebras`) with no `--model`, config-file `model`, or `UHM_MODEL`/per-provider alias sent that OpenAI default to a service that does not serve it. Each provider now has its own default model, applied only when no operator chose one:

- `openai` → `gpt-5.6-terra` (unchanged)
- `cerebras` → `gpt-oss-120b`
- `deepseek` → `deepseek-v4-flash`

`--model`, a config-file `model`, and the `UHM_MODEL` / provider-specific aliases still win, so every existing explicit configuration is unchanged. `--provider deepseek` with nothing else now resolves to `deepseek-v4-flash` and appears in `uhm config show` with source `(default)`.

## Privacy clarification: subcommand-scope tool help

The v0.5.0 subcommand probe reads a consented tool's deeper subcommand help under the same per-binary consent the top-level help flag already obtained — it gains no authority that first consent lacked, so nothing new leaves the device. `PRIVACY.md` now states this subcommand scope explicitly in the tool-help paragraph, so the privacy contract covers the deeper read in words as well as in behavior.

## Verification

The complete Rust suite (268 library + integration tests, including new coverage of the provider-default resolution and its explicit-choice precedence), `scripts/check-docs.py`, and a runtime check of `uhm --provider <id> config show` for all three providers plus an explicit `--model` override.
