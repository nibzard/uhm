# v0.3.0 — qualified provider selection

v0.3.0 introduces the provider-neutral execution and evidence framework needed to select models without weakening uhm's bounded-action contract.

- **Provider adapters.** OpenAI and Cerebras now share a canonical local action validator while retaining provider-specific wire handling. The CLI and configuration support explicit provider overrides, and `doctor all` can inspect every configured provider.
- **Evidence-based model selection.** Runtime selection is constrained by checked-in qualification policy and reviewed manifest entries. Automatic fallback is limited by request capabilities, provider credentials, and frozen compatibility fingerprints.
- **Benchmark fidelity.** A containerized execution benchmark uses production adapters and validators, a versioned 120-task corpus, semantic-family statistics, blinded judging, and separately reported deterministic outcomes.
- **Qualification controls.** Holdout sealing, manifest generation, audit schemas, redacted reporting, and strict run fingerprints make qualification evidence reproducible without treating development measurements as release approval.
- **Program contract hardening.** Generated programs use shared preflight and execution contracts, bounded artifact commits, stronger cache/history validation, and clearer diagnostics across initial and repaired attempts.
- **Documentation and privacy.** Configuration, model selection, qualification, program behavior, recovery, history, troubleshooting, and outbound-data documentation now cover the multi-provider path and its trust boundaries.

Release qualification remains fail-closed: no provider/model pair is automatically selected unless its reviewed manifest entry satisfies the frozen policy for the current request class.
