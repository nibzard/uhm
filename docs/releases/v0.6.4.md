# v0.6.4 — update UHM without provider credentials

v0.6.4 adds a built-in updater for standalone UHM installations and makes the
shared installer replace binaries atomically.

## What changed

### Built-in updates

`uhm update` now queries the latest published GitHub release before provider
configuration is loaded. It never requires an OpenAI or other model-provider
API key and does not send telemetry.

When a newer release exists, UHM runs its embedded installer pinned to that
exact tag. The installer downloads the native archive for the current platform,
verifies it against the release's `SHA256SUMS`, and replaces the executable in
its current directory. `--json` returns a structured update outcome.

The version comparison refuses to downgrade a development build when the
latest published release is older. Inherited target overrides are cleared so a
self-update cannot accidentally install an archive for another platform.

### Atomic installation

The release installer now writes the verified executable to a temporary file
in the destination directory and renames it over `uhm`. Because staging and
replacement occur on the same filesystem, an interrupted copy cannot leave a
partially written executable at the installed path. Temporary staging files are
removed on installer exit.

## Verification

The release passed `cargo fmt --all -- --check`,
`cargo clippy --all-targets --locked -- -D warnings`,
`cargo test --all-targets --locked`, `python3 scripts/check-docs.py`, the
installer portability test, package-content validation, and a live release
lookup confirming that newer development builds are not downgraded.
