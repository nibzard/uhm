# uhm v0.2.0

The second public release. It turns one natural-language terminal intent into one bounded local job and returns the useful result, then exits — deliberately smaller than a coding agent.

v0.2.0 publishes binaries built from the current main. Since v0.1.0, the bounded Python microprogram route, the inspectable local decision journal, optional parent-shell integration, and evidence-based recovery have landed, and natural language is now the default path. The installed `uhm --version` now matches the documented capability set.

## What ships

- **Natural language is the default path.** A plain intent runs as one bounded local job and returns the real output. `run`, `ask`, and `explain` remain available as explicit verbs.
- **Bounded Python microprograms.** For structured data, statistics, or multifile logic that would be contorted as a pipeline, `uhm` may generate one standard-library Python 3 program. It runs as `python3 -I -S` with a stripped environment, a private workspace, a 10-second wall limit, a 5-second CPU limit, and a 16 MiB output cap, with best-effort portable resource limits and a macOS-compatible skip path. See [bounded Python microprograms](https://github.com/nibzard/uhm/blob/main/docs/program.md).
- **Inspectable local decision journal.** Private append-only metadata receipts are on by default — state transitions, route, effects, process outcome, hashes, and timing, never intent, proposal, paths, input, or output. Inspect with `uhm history list|show|search|replay|export|prune|clear` and `uhm feedback good|bad`. See [local history](https://github.com/nibzard/uhm/blob/main/docs/local-history.md).
- **Optional parent-shell integration.** Bash, Zsh, and Fish users can install a nonce-bound invocation-only wrapper (`eval "$(uhm shell-init bash)"`) that applies one locally rendered typed action, so `cd`, `export`, and aliases take effect in the launching shell. It does not monitor commands or install prompt hooks. See [parent-shell integration](https://github.com/nibzard/uhm/blob/main/docs/shell-integration.md).
- **Bounded evidence-based recovery.** Opt-in preimages of eligible regular-file outputs from the managed Python artifact path. `uhm undo` restores only what it can hash-verify; a later edit is a conflict. `uhm restore --force` reapplies retained evidence; `uhm recover` proposes one reviewed, best-effort inverse and never claims it restored the original. See [bounded recovery](https://github.com/nibzard/uhm/blob/main/docs/recovery.md).
- **Piped-input privacy.** Explicit piped input travels with the model request by default; `--local-input` keeps the piped body on-device and sends only a byte-count, UTF-8 status, and optional format label.
- **Reproducible terminal demo** committed with a rebuild and privacy procedure, and a **competitor-landscape page** mapping direct alternatives, broader terminal and coding agents, and non-AI substitutes.

OpenAI requests use the Responses API with `store: false`. Content-free aggregate telemetry remains opt-out; metadata-only local receipts remain on by default. Read [PRIVACY.md](https://github.com/nibzard/uhm/blob/main/PRIVACY.md) for the exact boundary.

## Execution policy

Ordinary actions run immediately. Detected deletion, broad writes, privilege elevation, remote mutation, or process control pause unless `--force` is explicit. `--review` pauses every proposal; `--dry-run` prints exact command bytes and runs nothing. These warnings are advisory and are not a sandbox or a safety guarantee. Exit code zero is process evidence, not proof the intent was satisfied.

Persistent parent-shell actions are applied only through the optional wrapper; without it, `uhm` returns the exact typed `cd`, environment, or source action without pretending it was applied.

## Limits

Linux and macOS are supported; native Windows is not. `uhm` is not a background agent, does not provide universal undo, and does not sandbox model-generated commands or programs. macOS archives are not Developer ID signed or notarized in this release, so the first-download quarantine journey may require an explicit user approval.

The `uhm-cli` crate passes packaging and publish dry-run checks. Publishing to crates.io remains deferred until registry ownership is ready; GitHub binaries and `cargo install --git` are the supported channels.
