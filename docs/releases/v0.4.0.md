# v0.4.0 — the advertised surface works on a default install

v0.4.0 implements plan 17: corrective usability work from a black-box session on the shipped binary. Every command in `--help` now either works on a fresh installation or names, on its first invocation, the exact setting or flag that makes it work. No default changed: recovery capture and metadata-only history remain off-by-default, and nothing new leaves the device.

- **Behavior change: an impossible `--recoverable` refuses instead of proceeding.** A shell-route or parent-shell job given `--recoverable` used to report success having captured nothing. It now renders the reason a preimage cannot exist on that route and stops before execution; `--force` overrides, consistent with every other gate. Scripts that passed `--recoverable` on such jobs exited 0 before and now exit 11 — this is the change that makes this a minor release.
- **stdin can no longer stall a job.** `uhm` used to drain any non-TTY stdin to EOF before doing anything, so an inherited descriptor that never closed — CI runners, agent harnesses, `ssh` without `-n` — hung the job silently for up to the full execution timeout. A non-TTY stdin that produces no byte within a bounded deadline (`stdin_first_byte_timeout_ms`, default 1000, shown in `uhm config show`) now yields one stderr notice and the job proceeds without piped input. Once a first byte arrives, the read continues to EOF exactly as before, so a slow legitimate producer is never truncated.
- **The review prompt accepts what users type.** `y` at `Run, revise, edit, copy, cancel?` used to cancel the job — the same binary accepts `y`/`yes` at five other prompts. `y` and `yes` now run the reviewed command, an unrecognized key re-prompts once with the live options instead of silently cancelling, and the options render as full words so copy cannot be misread as cancel. EOF still cancels, and no other key gained executing power.
- **Recovery commands explain themselves.** On a default install, `undo`, `restore`, and `recover` now say that capture was never enabled, name `uhm recovery on` and `--recoverable`, and return the configuration status instead of a generic manifest-absent message. The `last` alias resolves to the most recent *restorable* manifest and names any newer run it skipped. `uhm recovery prune` gains `--all`, and the messages that pointed at plain `prune` — which could not remove retained snapshots — now name the form that can. A non-interactive `undo` names the exact command that completes it.
- **History answers "what did I run?"** `history list` prints each run's outcome and a local human-readable time instead of a raw epoch; `history show` renders events by default with the raw JSONL behind `--json`. Neither prints anything the allowlisted export withholds. `--help` marks `repair` and `recover` as requiring retained history, and `uhm doctor` reports whether they are usable on this install.
- **The idiomatic in-place rewrite passes.** The program validator hard-errored on `r = resource("target")` followed by `r.write_path.write_text(...)` — the natural shape for reading and writing one file — rejecting two of three identical rewrite attempts in the measured session. The checker now resolves a handle bound once to a local name, and any write it still cannot prove becomes a warning rather than a refusal. Validator reason codes no longer reach the terminal raw: each maps to a plain sentence, with the code kept under `-v` and in history.
- **Effects are rendered honestly, on every route.** The `Effects:` line distinguishes a declared-only effect from one actually detected, and the program route — which never showed effects at all — now renders the same line. Detection remains advisory; nothing gates on a mismatch.
- **The documented first run works in zsh.** The README's first example broke under zsh's glob expansion before `uhm` ever ran. Documented examples no longer depend on quoting luck, quoting guidance and a `noglob` alias note were added, piping a file into a question (`cat notes.md | uhm 'what is this about'`) is documented as the way to ask about a file's content, and a new test executes every fenced example in the README and docs under both zsh and bash. Plain `--dry-run` output ends with a newline when printed to a terminal and is byte-identical when piped.

Verification includes the complete Rust suite, the pty contract suite, strict Clippy, and the new documentation-example tests under both shells, on the same gates as v0.3.6.

The measured rejection rate for the in-place rewrite class across the benchmark corpus has not yet been re-run since the validator fix; that measurement is scheduled with the next benchmark slot. Recovery capture and full-intent history retention remain deliberate opt-ins; this release changes what the commands say, not what is stored.
